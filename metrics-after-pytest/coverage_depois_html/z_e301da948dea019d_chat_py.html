15#: The conversation a page that names none is in. 

16#: 

17#: ⛔ THE SAME OBJECT the server persists under, not a second string that 

18#: matches it. The point is not a coincidence: every client written before this 

19#: existed keeps landing on one conversation driving one browser. That was 

20#: declared twice - `"default"` here and `DEFAULT_SESSION_ID` in the mcp 

21#: package - with a comment saying the two had to agree and a test asserting 

22#: this one equalled the LITERAL `"default"`. Moving the server's default would 

23#: therefore have left the interface writing `chats/default.json` while the 

24#: server wrote `sessions/lavoro.json`, with the test that names the invariant 

25#: still green. One declaration cannot disagree with itself. 

26DEFAULT_CHAT_ID = DEFAULT_SESSION_ID

28#: What a conversation is called before it has been asked anything. 

29UNNAMED = "New chat"

31#: Kinds that are STATE rather than conversation: told to whoever is listening 

32#: NOW, and never written into the transcript. 

33#: 

34#: `busy` has been here from the start - replaying it to somebody who opens the 

35#: page later would show a spinner for work that finished an hour ago. 

36#: 

37#: ⛔ `fresh` JOINED IT IN 0.57.0, AND IT COULD EAT A TYPED SENTENCE. It is the 

38#: word that tells every page to wipe, and `reset` emits it immediately after 

39#: clearing the history - so it landed in the now-empty transcript and became 

40#: the ONE thing a cleared conversation had written down. Found by reading a 

41#: real saved file, not by a test: the developer's own `default.json` held 

42#: exactly one event, and it was this. 

43#: 

44#: What that costs is small and is the one thing this interface must not do. A 

45#: replayed `fresh` runs `wipe()` in the page, and `wipe()` calls 

46#: `setQueued(null)`: so a person who had typed a follow-up while the agent 

47#: worked, on a conversation that had been cleared at any point in its past, 

48#: lost that sentence the moment the stream reconnected from before the stored 

49#: `fresh` - which is exactly what a server restart does. Nothing said so. 

50#: 

51#: The live path is untouched: `/chat/fresh` still emits it and every listener 

52#: still wipes, which is what makes two tabs agree. A page that arrives LATER 

53#: needs no command, because what it is handed is already the empty transcript 

54#: the command would have produced. 

55NOT_SAID = ("busy", "fresh")

95 def save(self) -> None: 

96 """Write this conversation down as it stands. 

97 

98 Called when the conversation CHANGES - a turn ended, it was renamed, it 

99 was reset - and not on a timer, for the reason the browsers are saved 

100 the same way: a file written on a tick is a version of the session that 

101 existed only between two ticks. 

102 

103 ⛔ BOTH TRANSCRIPTS, and saving only one would be a promise the other 

104 half cannot keep. The page draws `history`; the model holds `messages`. 

105 Reopening with only the first gives somebody a conversation they can 

106 read and cannot continue, under a follow-up box that still says "and now 

107 sort them by price" will work. 

108 

109 The turn is already finished and answered, and losing it to a full disk 

110 would be a strange way to report a full disk. 

111 

112 ⛔ WHAT GOES DOWN IS WHAT WAS SAID, AND THE SYSTEM MESSAGE IS NOT. It is 

113 what this build asks the model to be, rebuilt on every run from the 

114 prompt plus the server's own instructions, and `remember` has dropped 

115 the saved one on the way back in since 2026-09-08 - so writing it was 

116 writing something nothing would ever read. `said_only` is where that 

117 rule lives, for this side and that one. 

118 """

121 said_only(getattr(self._brain, "messages", None)), 

122 self.usage)

160 def reset(self) -> bool: 

161 """Start a fresh conversation, keeping the browser where it is. 

162 

163 ⛔ THIS IS A COST AND LATENCY CONTROL, not a tidiness feature, and 

164 until it existed there was no way to reach it short of killing the 

165 process. Every turn resends the whole transcript, so the transcript is 

166 the bill and it is also the wait: measured on this interface, a first 

167 instruction on a fresh process carries 3,106 prompt tokens and the 

168 agent moves 4.1 s after the click; by the third instruction of the same 

169 session the first turn already carries 38,207 and the wait is 6.7 s. 

170 Nothing trimmed it, so it only grew. 

171 

172 The browser is deliberately left alone. Someone who has logged in 

173 somewhere and wants to drop the transcript should not lose the session 

174 they built, and the two have no reason to be tied. 

175 

176 Refused while a run is in flight rather than cancelling it: throwing 

177 away a transcript that something is still writing into is the kind of 

178 surprise a person cannot undo. 

179 """ 

180 if self.busy: 

181 return False 

182 forget = getattr(self._brain, "forget", None) 

183 if callable(forget): 

184 forget() 

185 self.history.clear() 

186 self._epoch = str(int(time.time() * 1000)) 

187 return True

207 @property 

208 def busy(self) -> bool: 

209 """Whether an instruction is in flight. The one place that knows. 

210 

211 ⛔ TWO PLACES ANSWERED THIS, AND FOR A MOMENT THEY DISAGREED. This read 

212 the lock, which `send` takes only once its task first runs, and `start` 

213 read nothing at all. Between `create_task` and that first step the lock 

214 was free while a run was already on its way, so a second `/chat/send` 

215 in that window was accepted, its task replaced the handle, and Stop 

216 could no longer reach the run driving the browser. The lock alone misses 

217 the start of a run; the handle alone would miss a `send` awaited 

218 directly, without `start`. So both, here, and every caller - `start`, 

219 `reset`, a listener joining - asks this. 

220 

221 The handle cannot answer for a run that ended: it is asked whether its 

222 task is done, and the task finishes in the same step that releases the 

223 lock, after the closing `busy 0` and with no await in between. 

224 """ 

225 task_alive = self._task is not None and not self._task.done() 

226 return task_alive or self._busy.locked()

228 def start(self, text: str) -> bool: 

229 """Run an instruction detached, keeping the handle so it can be stopped. 

230 

231 The task is held for exactly that reason. Firing and forgetting is one 

232 line shorter and makes the stop button a decoration. 

233 

234 Refused, answering False, while another instruction is in flight: two 

235 tabs can post before either sees the busy event, and replacing the 

236 handle would make Stop cancel the waiting turn while the run already 

237 driving the browser carries on. The page queues a refused sentence the 

238 way it queues one typed while it already knows the agent is busy. 

239 """ 

240 if self.busy: 

241 return False 

242 self._task = asyncio.create_task(self.send(text)) 

243 return True

245 def stop(self) -> bool: 

246 t = self._task 

247 if t is not None and not t.done(): 

248 t.cancel() 

249 return True 

250 return False

270 # The cancellation lands at the next await, and since the model 

271 # request runs in a thread that is either the request itself or 

272 # the tool call after it - so stop is prompt rather than "after 

273 # the step in flight", which is what this comment used to say 

274 # and what the loop used to do. 

275 # 

276 # Prompt is not free: a model request already sent finishes in 

277 # its thread and its answer is discarded, so a run stopped 

278 # mid-turn is still billed for that reply. Stopping cuts what 

279 # comes next, never what is already in the air.

281 # `err` with the single word `stopped`, so a deliberate and 

282 # correct action was answered with a red box, announced to a 

283 # screen reader as "error stopped", and any step in flight was 

284 # flipped to the failed state. The page treated the user's own 

285 # instruction as a fault. 

286 await self.emit("note", "Stopped.") 

287 raise 

288 except Exception as exc:

290 # RAW JSON INTO THE CONVERSATION. It is the one line in the 

291 # product a person reads at the exact moment something has gone 

292 # wrong, and it said nothing about what to do next or about the 

293 # instruction they had just lost sight of. The detail stays - 

294 # it is the only clue when the cause is real - behind a sentence

297 await self.emit("err", "The turn ended early. What you asked is " 

298 "still in the transcript, so you can send it " 

299 "again once this is dealt with. (%s%s)"

305 # mid-run is a version of the conversation that existed for a 

306 # moment, and this is the moment it is worth keeping. Stopped 

307 # and failed runs are saved too - what was asked and how far it 

308 # got is exactly what somebody reopens the session to see.
